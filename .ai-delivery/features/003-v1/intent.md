# 意图（第 1 版，草稿，尚未在 G1 确认）

> 本文件由平台根据意图的权威记录生成，是只读副本：任何会话修改它都会被拒收。意图以会话提示中 [交付输入] 的 intent 为准。

## 要解决的问题

两个问题一并修复（问题报告 IR-001 与业务负责人试用反馈）。（1）用户看到的问题：用“系统声音”播放韩国电影时，部分字幕直接显示韩文原文，没有翻译成中文；换一部韩国电影或稍后重放又正常，英文、日文电影没有出现这个问题；截图里连续几条字幕都是韩文原文，后面又恢复中文。服务日志中同一时段的韩语翻译请求都是正常完成（没有错误码），所以“显示原文”很可能不是请求失败，而是翻译结果本身不是中文，或者界面在某种情况下显示了识别原文。用户期望的是中文字幕只显示中文译文，不能静默显示外语原文。（2）运行环境自动发现的问题 IR-001（诊断结论为产品缺陷）：客户端按设计中止被新结果取代的翻译请求时，服务端把它记成 error 级别的 unhandled_error / internal_error，触发了“出现即报”的告警，形成误报。

## 范围

1. 查清韩语字幕显示原文的原因并修复：修复后中文字幕只显示中文译文；翻译结果不是中文时，不能把非中文内容当作字幕显示（例如重新翻译一次，仍不成功则给出中文提示），不能静默显示外语原文。适用于麦克风与系统声音两种输入，以及主页面字幕与悬浮字幕小窗。2. 补一个能稳定复现的测试：用韩语素材（以及至少一种其它非英语语言）验证定稿字幕全部是中文。3. 客户端主动中止或断开 /api/translations 的流式响应属于预期情况，不再以 error 级别记录，只保留现有的 client_aborted 信息级记录；真正未预期的服务端异常仍以 error 级别记录。4. 补一个场景：流式翻译进行中由客户端中止（首个片段写出前和写出后两种时机），断言不产生 error/fatal 级日志并产生 client_aborted 记录。5. 现有功能（麦克风与系统声音两种输入、流式字幕、悬浮字幕小窗、界面）保持不变，不能因为本次修复变差。

## 不做的事

- 不新增翻译目标语言或源语言，不改变连续语言自动识别的候选语言范围。
- 不改变客户端“中止被新结果取代的翻译请求”这一既有设计，只修正服务端对它的日志级别。
- 不改变告警规则本身（“出现即报”保持不变），通过不再产生误报的 error 级日志解决。
- 不降低真正未预期的服务端异常的日志级别。
- 不改变麦克风与系统声音两种输入、流式字幕、悬浮字幕小窗与界面的现有行为和外观（本次新增的中文提示除外）。
- 不保存任何字幕或发言内容，日志中不记录客户内容（宪章“安全与隐私”）。

## 验收标准

- **AC-1**：用“系统声音”输入播放韩语素材，运行结束时主页面字幕区出现过的每一条定稿字幕都是中文译文或本次约定的中文提示，没有任何一条定稿字幕包含韩文字母（谚文）。
- **AC-2**：用至少一种其它非英语语言素材（例如日语）重复 AC-1 的测试，每一条定稿字幕都是中文译文或本次约定的中文提示，不包含该语言的原文文字（如日文假名）。
- **AC-3**：AC-1 与 AC-2 的测试是能稳定复现的自动化测试：对同一素材连续运行不少于 3 次，每次判定结果一致。
- **AC-4**：当某一句的翻译结果不是中文时（可由测试使翻译返回非中文内容来触发），界面不会把这段非中文内容作为该句字幕显示，也不会显示该句的识别原文；系统重新翻译该句一次，重新翻译得到中文时显示中文译文。
- **AC-5**：当某一句重新翻译后结果仍不是中文时，该句不显示任何外语内容，并给出中文提示（提示的形式与位置以待澄清问题 Q-1 的答案为准）。
- **AC-6**：悬浮字幕小窗打开时，在 AC-1、AC-4、AC-5 的情形下小窗显示的字幕与主页面逐条一致，小窗中同样不出现非中文的定稿字幕。
- **AC-7**：流式翻译进行中、服务端写出首个片段之前由客户端中止 /api/translations 请求：服务端在该请求期间不产生任何 error 或 fatal 级别的日志，并产生一条 client_aborted 信息级记录。
- **AC-8**：流式翻译进行中、服务端已写出首个片段之后由客户端中止或断开 /api/translations 请求：服务端在该请求期间不产生任何 error 或 fatal 级别的日志，并产生一条 client_aborted 信息级记录。
- **AC-9**：/api/translations 处理中发生真正未预期的服务端异常（非客户端中止）时，服务端仍以 error 级别记录该异常。
- **AC-10**：AC-7、AC-8 产生的日志中不包含发言原文、译文或任何凭据。
- **AC-11**：修复后，现有麦克风输入、系统声音输入、流式字幕（临时字幕与定稿字幕）、悬浮字幕小窗与界面的既有验收测试全部通过。

## 假设

- “中文”指简体中文译文；在 Q-2 得到回答前，按推荐答案理解：译文中夹带的人名、品牌、缩写、数字等不视为“非中文”，谚文、日文假名等源语言文字一律视为非中文。
- “至少一种其它非英语语言”默认使用日语（已在现有候选语言中）。
- 测试素材沿用现有方式由 TTS 合成，并通过“系统声音”路径播放。
- “重新翻译一次”指对同一句再发起一次定稿翻译，只重试一次。
- 外部翻译与语音服务的验收测试针对真实测试服务执行；“翻译结果不是中文”的分支可由测试受控触发，但不以 Mock 替代 AC-1～AC-3 的功能验收证据（宪章“测试与质量”）。
- client_aborted 记录沿用现有的信息级记录格式与字段，不新增日志内容。

## 待澄清问题与答案

### Q-1：某一句重新翻译后仍不是中文时，“给出中文提示”以什么形式出现？这决定用户在字幕区实际看到的内容。

- 出处：需求原文第 1 条：“翻译结果不是中文时……（例如重新翻译一次，仍不成功则给出中文提示）”；现有行为是翻译失败的句子直接从字幕区移除、不留提示。
- 推荐答案：在该句字幕的位置显示一条区别于正常译文样式的中文提示（如“（此句未能翻译成中文）”），主页面与小窗一致。
- 备选答案：不在字幕区占位，只在状态区短暂显示中文提示（如“有字幕未能翻译成中文，已跳过”），该句从字幕区移除。；两者都做：字幕位置显示占位提示，同时状态区短暂提示。
- 答案：尚未回答

### Q-2：判定“字幕全部是中文”时，译文中保留的拉丁字母（人名、品牌、缩写如 OK、iPhone）是否允许？这决定验收的判定标准和可能被替换成提示的句子数量。

- 出处：需求原文第 1 条：“中文字幕只显示中文译文”“验证定稿字幕全部是中文”。
- 推荐答案：允许：译文以中文为主即可，夹带的拉丁字母专名、缩写与数字可以保留；只禁止出现源语言文字（如谚文、日文假名）或整句未翻译。
- 备选答案：严格：除标点和数字外只允许汉字，出现任何外文字母都视为非中文。；只禁止整句或大段未翻译的外语，不对个别外文字符做判定。
- 答案：尚未回答

### Q-3：“只显示中文”的要求是否也适用于说话过程中的临时字幕（临时中文译文），还是只针对定稿字幕？

- 出处：需求原文第 1 条：“中文字幕只显示中文译文……不能静默显示外语原文”，而测试要求只写“验证定稿字幕全部是中文”；现有产品在说话过程中会显示临时译文。
- 推荐答案：同样适用：临时译文不是中文时不显示（保留上一条临时译文或暂不显示），但临时字幕不做重新翻译、不给提示。
- 备选答案：只针对定稿字幕，临时字幕保持现状。；临时字幕与定稿字幕完全同样处理（含重新翻译与中文提示）。
- 答案：尚未回答

### Q-4：重新翻译后仍不是中文的句子，是否计入现有“连续 3 句翻译失败即停止翻译并提示‘翻译已中断’”的规则？这决定连续出现非中文结果时翻译是继续还是被停止。

- 出处：现有产品行为（src/web/captionPipeline.ts 中连续失败达到 3 次停止翻译）；需求原文第 3 条“现有功能保持不变”。
- 推荐答案：不计入：只给出中文提示，翻译继续进行。
- 备选答案：计入：与其它翻译失败同样处理，连续 3 句后停止翻译并提示“翻译已中断”。
