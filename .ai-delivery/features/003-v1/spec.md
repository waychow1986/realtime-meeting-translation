> 依据：已确认的意图第 2 版（交付输入，含 Q-1～Q-4 的人工答案）与需求原文 `request.json`。既有产品行为以第 1 版规格 `.ai-delivery/features/001-v1/spec.md`（下称“第 1 版规格”）与第 2 版规格 `.ai-delivery/features/002-v1/spec.md`（下称“第 2 版规格”）为基线；本规格只描述本次修复改变或新增的行为，未提及的既有行为保持不变。

## 用户故事

### US-301 外语电影的字幕只出现中文（P1）
作为用“系统声音”或麦克风看韩国、日本等外语视频的使用者，我希望字幕区和小窗里每一句都只出现中文译文，而不是突然出现看不懂的外语原文，以便全程理解内容。引用 INT-301；覆盖 AC-1、AC-2、AC-4、AC-6、AC-12。

### US-302 翻不成中文的句子有明确提示（P1）
作为使用者，当某句确实没能翻译成中文时，我希望在该句的位置看到一条清楚但不刺眼的中文提示，并且翻译继续进行，以便知道这里漏了一句而不是看到乱码或外语。引用 INT-301；覆盖 AC-5、AC-6。

### US-303 “只显示中文”可被稳定验证（P1）
作为业务负责人，我希望有一组用韩语和日语素材、能稳定复现的自动化测试证明定稿字幕全是中文，以便确认问题已被修复且不再复发。引用 INT-302；覆盖 AC-1、AC-2、AC-3、AC-4。

### US-304 中止请求不再引发误报（P1）
作为告警接收者，我希望客户端按设计中止或断开翻译请求时服务端不再记录 error / fatal 级日志，而真正的服务端异常仍被记录为 error，以便“出现即报”的告警只在真正出问题时响起。引用 INT-303、INT-304；覆盖 AC-7、AC-8、AC-9、AC-10。

### US-305 现有体验不变差（P1）
作为现有使用者，我希望两种输入、流式字幕、悬浮小窗与界面在修复后表现如常。引用 INT-305；覆盖 AC-11。

### US-306 问题原因有据可查（P2）
作为业务负责人，我希望技术方案写明“韩语字幕显示原文”的根因及证据，并说明修复如何针对它。引用 INT-301；覆盖 AC-13。

## 功能需求

### 中文判定（适用于临时与定稿字幕、两种输入、主页面与小窗）

- **FR-301**：一段翻译结果在满足以下全部条件时判定为“中文”，否则判定为“非中文”（Q-2 人工答案）：
  1. 不含谚文（韩文字母）；
  2. 不含日文假名（平假名、片假名，含半角片假名）；
  3. 不含汉字、拉丁字母以外的其它文字的字母（如西里尔字母、泰文、阿拉伯文等）；
  4. 至少含有一个汉字（整句没有任何汉字视为“整句未翻译”）。
  数字、标点、空白、符号以及夹带的拉丁字母专名、品牌与缩写（如 OK、iPhone）不影响判定。（AC-1、AC-2、AC-4、AC-12）
- **FR-302**：全部由汉字组成、未经翻译的日文无法与中文区分，按 FR-301 判定为“中文”；这一局限已被接受，不作为缺陷（AC-2）。

### 字幕区永不显示识别原文与非中文内容

- **FR-303**：在任何时刻、任何字幕状态（临时、定稿中、定稿、中断）下，主页面字幕区与悬浮字幕小窗都不显示语音识别得到的原文，也不显示被判定为“非中文”的翻译结果或其任何片段。（AC-1、AC-2、AC-4、AC-6、AC-12）

### 临时字幕

- **FR-304**：说话过程中，某句的临时译文判定为“中文”时按既有方式显示并更新；判定为“非中文”时不显示，该句继续显示上一条已显示的中文临时译文；若该句此前还没有显示过任何临时译文，则保持既有的“尚无译文”显示状态（不填入任何文字）。临时译文为“非中文”时不重新翻译、不显示提示。（AC-12；Q-3）

### 定稿字幕

- **FR-305**：一句话结束后，该句的定稿译文只在整句定稿结果判定为“中文”之后才替换该句字幕；在得到判定之前（包括定稿翻译流式返回期间与重新翻译期间），该句继续显示其最后一条中文临时译文，不出现空白、不缩短。由此带来的少量显示延迟被接受（意图假设“定稿译文先判定为中文再显示”）。（AC-4）
- **FR-306**：定稿结果判定为“中文”时，该句变为定稿字幕，显示该中文译文，此后不再改变（与第 1、2 版规格一致）。（AC-1、AC-2、AC-4）
- **FR-307**：定稿结果判定为“非中文”时，系统对同一句再发起一次定稿翻译（每句最多一次）；重新翻译的结果判定为“中文”时按 FR-306 显示。（AC-4）
- **FR-308**：重新翻译的结果仍判定为“非中文”时，该句变为定稿状态，在该句字幕位置显示中文提示“（此句未能翻译成中文）”，此后不再改变；该句不显示任何外语内容。提示的样式与正常中文译文明显不同（至少一项可见样式不同，如颜色、字形或标记，不依赖悬停），且不使用警示红色、闪烁、动画或大于正常字幕的字号；提示文字满足第 2 版规格 FR-129 对临时字幕的对比度要求，并随字号档位一起变化。（AC-5；Q-1）
- **FR-309**：显示中文提示的句子不计入“连续 3 句翻译失败即停止翻译并提示‘翻译已中断’”的规则：既不算作一次翻译失败，也不改变此前的连续失败计数；翻译继续进行，后续句子照常产生字幕。（AC-5；Q-4）
- **FR-310**：显示中文提示的句子在“每句语音恰好对应一条定稿字幕、按顺序、不重不漏”的既有规则中，算作该句的那一条定稿字幕。（AC-1、AC-5、AC-11）
- **FR-311**：翻译请求本身失败（服务不可用、超时、被限流、网络中断等）时，保持既有处理：按既有规则重试，仍失败则该句从字幕区移除并按既有规则计入连续失败；这包括“重新翻译”这一次请求失败的情况。本次修复不把请求失败显示为中文提示。（AC-11）

### 悬浮字幕小窗

- **FR-312**：悬浮字幕小窗打开时，其中每一句的显示内容（中文临时译文、中文定稿译文或中文提示）及样式区分与主页面逐条一致、同步更新；小窗同样遵守 FR-303～FR-310。（AC-6）

### 停止与重新开始

- **FR-313**：使用者在某句判定或重新翻译尚未完成时点击“停止”（或系统声音共享结束），按既有停止规则处理：该句此后不再改变，保留停止时显示的中文临时译文；不会在停止后再出现该句的定稿译文、提示或任何非中文内容。（AC-4、AC-11）

### 服务端日志：客户端中止

- **FR-314**：`/api/translations` 流式翻译进行中，客户端主动中止请求或连接断开（包括关闭页面、网络断开），无论发生在服务端写出首个翻译片段之前还是之后，服务端在处理该请求期间不产生任何 error 或 fatal 级别的日志。（AC-7、AC-8）
- **FR-315**：每个被客户端中止或断开的 `/api/translations` 请求产生且只产生一条现有格式的 `client_aborted` 信息级记录；记录沿用现有字段，不新增字段。（AC-7、AC-8）
- **FR-316**：客户端中止或断开不会导致服务进程退出或重启；之后的翻译请求照常得到处理。（AC-7、AC-8；意图假设中的“进程级未处理异常路径也需排除客户端中止”）
- **FR-317**：`/api/translations` 处理中发生非客户端中止引起的、未预期的服务端异常时，服务端仍以 error 级别记录该异常，返回给客户端的结果与现有行为一致。（AC-9）
- **FR-318**：FR-314～FR-317 涉及的日志不包含发言原文、译文或任何凭据；“出现即报”的告警规则保持不变。（AC-10；意图“不做的事”）

### 不退化

- **FR-319**：除 FR-304～FR-313 明确改变的行为外，麦克风输入、系统声音输入、流式字幕（临时字幕在说话过程中出现并更新、句末定稿）、悬浮字幕小窗与界面的行为与外观与第 1、2 版规格一致，其既有验收测试全部通过。英语素材的定稿字幕仍须与参考译文意思一致（第 1 版规格 FR-010、第 2 版规格 FR-113）。（AC-11）
- **FR-320**：不新增目标语言或源语言，不改变语言自动识别的候选语言范围；不改变客户端中止被新结果取代的翻译请求的行为。（意图“不做的事”）

## 产品质量要求

当前没有获批准的额外质量要求。本次只有意图明确规定的可判定要求：AC-3 的“同一素材连续运行不少于 3 次、每次判定一致”（见 SC-303），以及 FR-308 对提示样式的可判定描述（沿用第 2 版规格 FR-129 的对比度要求）。不新增时延、可用率或其它数值目标。

## 前置条件与触发条件

- 字幕相关行为（FR-301～FR-313）：页面处于“正在听”，输入为麦克风或系统声音；触发为收到某句的临时或定稿翻译结果。
- 中止相关行为（FR-314～FR-316）：某个 `/api/translations` 流式请求正在处理；触发为客户端中止或连接断开。
- 异常相关行为（FR-317）：某个 `/api/translations` 请求处理中发生非客户端中止引起的未预期异常（验收时允许由测试注入受控触发，AC-9）。
- “非中文”分支（FR-307、FR-308）：真实服务下偶发；验收时允许由测试使翻译返回非中文内容受控触发（AC-4）。

## 行为模型

### US-301 字幕只出现中文

- 正常：韩语（或日语、英语）一句话说话过程中出现中文临时字幕并更新 → 句末定稿结果判定为中文 → 替换为中文定稿字幕。（FR-301、FR-304～FR-306）
- 临时译文为非中文：该次结果不显示，字幕保持上一条中文临时译文；后续临时译文为中文时照常更新。（FR-304）
- 定稿结果为非中文：该句继续显示最后一条中文临时译文 → 重新翻译一次 → 得到中文则显示中文定稿字幕。（FR-305、FR-307）
- 任何分支下都不显示识别原文。（FR-303）

### US-302 翻不成中文的句子有提示

- 重新翻译仍为非中文：该句定稿为中文提示“（此句未能翻译成中文）”，样式区别于正常译文；翻译继续，后续句子正常出字幕；不计入连续失败。（FR-308～FR-310）
- 连续多句都得到中文提示：每句各显示一条提示，翻译不会因此停止。（FR-309）
- 提示句与请求失败句交替：请求失败按既有规则计数；提示句既不计入也不清零该计数。（FR-309、FR-311）

### US-303 稳定验证

- 用韩语、日语合成素材经“系统声音”路径各运行不少于 3 次，每次所有定稿字幕都通过 FR-301 判定或为中文提示。（SC-301～SC-303）

### US-304 中止不误报

- 首个片段写出前中止：无 error / fatal 日志；一条 `client_aborted` 信息级记录；服务继续可用。（FR-314～FR-316）
- 首个片段写出后中止：同上。（FR-314～FR-316）
- 真正的未预期异常：记录为 error；客户端得到与现有一致的结果。（FR-317）

### US-305 不退化

- 第 1、2 版规格的全部用户场景照常成立；唯一可见差异是定稿译文在判定为中文之后才出现，以及可能出现的中文提示。（FR-319）

### US-306 根因可查

- 技术方案记录根因、证据与修复针对性；无法确定唯一根因时列出已排除与未排除的可能及依据。（AC-13）

## 业务状态、业务数据规则与不变量

每句字幕的状态（在第 1、2 版规格基础上）：

| 状态 | 显示内容 | 进入条件 | 离开条件 |
| --- | --- | --- | --- |
| 临时 | 最近一条判定为中文的临时译文（尚无时为空） | 该句开始被识别 | 句子结束 → 定稿中；停止 → 按既有停止规则 |
| 定稿中 | 最后一条中文临时译文 | 句子结束 | 定稿结果为中文 → 定稿（译文）；为非中文且未重新翻译过 → 定稿中（重新翻译）；重新翻译仍为非中文 → 定稿（提示）；请求失败 → 按既有规则重试或移除；停止 → 按既有停止规则 |
| 定稿（译文） | 中文定稿译文 | 见上 | 不再改变 |
| 定稿（提示） | “（此句未能翻译成中文）”，提示样式 | 见上 | 不再改变 |

不变量：

1. 字幕区与小窗中显示过的任何文字，要么是判定为中文的译文，要么是中文提示，要么是第 1、2 版规格既有的中文界面文字；从不出现识别原文或判定为非中文的内容。（FR-301、FR-303）
2. 每句最多重新翻译一次；临时译文从不触发重新翻译。（FR-304、FR-307）
3. 定稿字幕一经出现不再改变或移除；每句恰好一条定稿条目（译文或提示），顺序与语音一致（FR-306、FR-308、FR-310；第 2 版规格不变量 4）。
4. 主页面与小窗在同一时刻显示同一组条目、同一内容与样式区分。（FR-312）
5. 客户端中止或断开 `/api/translations` 永远不产生 error / fatal 日志，每次恰有一条 `client_aborted` 信息级记录；未预期异常永远以 error 记录。（FR-314～FR-317）
6. 不保存任何字幕、识别文本或译文；日志不含客户内容与凭据。（FR-318）

## 安全、隐私与可访问性行为

- 识别原文、译文与中文提示均不保存；重新翻译所需的内容只在该句处理期间使用（宪章“安全与隐私”；FR-318）。
- `client_aborted` 记录与 error 记录都不含发言原文、译文或凭据；不新增日志字段（AC-10；FR-315、FR-318）。
- 中文提示的可读性：满足第 2 版规格 FR-129 对临时字幕的对比度要求，并随字号档位变化（FR-308）。不新增正式可访问性等级要求。

## 性能、可靠性与其他质量边界

当前没有获批准的额外要求。意图已接受“定稿译文先判定为中文再显示”带来的少量显示延迟（FR-305），本规格不为其设定数值上限；第 1、2 版规格中“临时字幕在句子结束前出现并更新”的既有验收（如第 2 版 IQA-103）仍须通过（FR-319）。

- 对 FR-301 的中文判定做覆盖各类文字（谚文、平假名、片假名、半角片假名、西里尔等其它文字、纯拉丁字母、汉字夹拉丁专名与数字、全汉字日文）的独立检查。
- 对字幕状态（临时 / 定稿中 / 定稿译文 / 定稿提示）的转换、每句最多重新翻译一次、提示不计入连续失败、请求失败保持既有处理、停止期间不再变化做独立检查。
- 对 `/api/translations` 在首个片段前后被中止、注入未预期异常三种情况做日志级别与 `client_aborted` 记录的检查。
- 以上检查可以使用受控替身，但不作为 AC-1～AC-3 的功能验收证据。

### Independent QA 验收

- 按“验收场景”执行 IQA-301～IQA-313。IQA-301、IQA-302 针对真实语音与翻译服务，各连续执行不少于 3 次；IQA-303～IQA-306、IQA-310、IQA-312 按通用约定受控触发；IQA-303 的同一测试须在修复前的版本上有一次失败运行记录。
- IQA-311 运行第 1、2 版既有自动化验收测试的全集。
- 所有日志检查只记录数量与级别统计，不在证据中保存客户内容。

### 总体通过与失败标准

- 通过：IQA-301～IQA-313 全部通过，且 PQ-301 得到人工答案并已按答案补充 IQA-301、IQA-302 的判定。
- 失败：任一场景失败；或字幕区 / 小窗在任何时刻出现谚文、日文假名、识别原文或受控返回的非中文内容；或客户端中止期间出现任何 error / fatal 日志；或日志中出现客户内容或凭据。

## 假设、依赖与范围外边界

假设（来自已确认意图或对其的直接应用，不新增验收标准）：

- “中文”指简体中文译文；判定规则见 FR-301（Q-2）。FR-301 第 3 项“其它非拉丁、非汉字文字也视为非中文”是对“禁止源语言文字”的直接应用：候选语言范围可配置，任何非拉丁、非汉字的源语言文字都属于此类。
- “重新翻译一次”指对同一句再发起一次定稿翻译，每句最多一次；它独立于既有的“请求失败后重试”规则：请求失败的重试照旧，重新翻译这一次请求若失败，按既有的请求失败处理（FR-311）。
- “不计入连续 3 句失败”理解为提示句既不计为失败、也不清零已有的连续失败计数（与既有“不计入”类失败的处理一致，FR-309）。
- 句子结束时若还未显示过任何中文临时译文，判定前该句保持既有的“尚无译文”显示（FR-304、FR-305）；“不留空白”针对已显示过临时译文的句子。
- 提示文字固定为 Q-1 答案给出的“（此句未能翻译成中文）”。“不刺眼”以 FR-308 列出的可判定条件表达。
- 测试素材沿用现有方式由语音合成生成，并通过“系统声音”路径播放；“其它非英语语言”使用日语（已在现有候选语言中）。
- `client_aborted` 记录沿用现有格式与字段；进程级未处理异常路径也排除客户端中止（FR-316）。

依赖：现有 Azure Foundry 语音服务与大模型实例（测试环境）；第 1、2 版规格的既有验收测试。

范围外：见“产品目标与边界”。
