# 独立测试计划 · 系统声音实时翻译（002-v1）

> 依据：已确认的意图第 2 版（AC-01～AC-12，含 Q-01、Q-02 人工答案）与规格 `spec.md`（验收场景 IQA-101～IQA-123，含 PQ-001～PQ-005、DD-101 人的决定）。本计划不依据实现代码。
> 执行脚本：`runtime/qa-run.sh`（与本计划一同锁定）。脚本自包含，不依赖仓库源码，测试素材在脚本中合成。
> 结果中的场景编号只用规格中的 IQA-101～IQA-123；边界与错误情况写成该场景的检查点（`checkpoints`），检查点编号形如 `IQA-102-c3`。

## 1. 范围

- 在真实测试环境中部署的候选上，逐条执行 IQA-101～IQA-123；语音识别与翻译使用平台注入的现有依赖 `test` 实例，不使用 Mock（宪章“测试与质量”）。
- 系统声音只以“共享标签页声音”验收（PQ-001）。Windows 整个屏幕系统声音、macOS 组合、字幕小窗“悬浮在全屏视频 / 会议软件之上可见”（DD-101）、真实点击浏览器“停止共享”（PQ-005，以 IQA-107 为等效证据）不在本计划范围，脚本不为这些点生成任何证据。
- 翻译含义一致性只用清晰的合成英语语音判定（PQ-002）。

## 2. 执行环境与工具

| 项目 | 做法 |
| --- | --- |
| 浏览器 | Playwright 自带 Chromium（Chrome for Testing 同源内核，视作“最新版 Chrome / Edge”），以**有头模式**运行在 Xvfb 虚拟显示上（无头模式不支持 `getDisplayMedia`，已在编写计划时实测）；每组场景使用独立的 Xvfb 显示与全新浏览器配置（无插件）。IQA-109、IQA-123 使用 Playwright 自带 Firefox。 |
| 共享标签页声音 | Chromium 启动参数 `--auto-select-tab-capture-source-by-title=<素材页标题>`：点击“开始”后浏览器自动在共享弹窗中选择素材标签页并带音频（规格通用约定允许）。素材页由脚本在本地 HTTP 服务上提供，用 `<audio>` 播放合成语音；带有易辨认的画面（红绿棋盘与 `QA-CANARY` 大字）用于 IQA-117。 |
| 共享不含声音 | 启动参数 `--auto-select-desktop-capture-source=Entire screen`：Linux 上共享整个屏幕不带音频轨道（已实测），即规格 IQA-111 中“在验收环境不能带声音的内容（如整个屏幕）”。 |
| 取消共享 | 不带自动选择参数启动，共享弹窗真实弹出后，脚本经 X 服务器 XTEST 扩展向弹窗发送 Esc 键（等同用户点“取消”），浏览器以 `NotAllowedError` 拒绝（已实测）。 |
| 麦克风（麦克风模式） | Chromium 假设备：`--use-fake-device-for-media-stream --use-fake-ui-for-media-stream --use-file-for-fake-audio-capture=<素材>.wav%noloop`，浏览器真实走麦克风采集路径，声音为合成语音。麦克风被拒绝用 `--deny-permission-prompts` 且不授予权限。 |
| 麦克风干扰（系统声音模式） | 假设备参数会使共享也变成假画面，不能与真实标签页共享同时使用，因此系统声音模式下用页面初始化脚本包装 `navigator.mediaDevices.getUserMedia`：记录每次调用；若应用调用麦克风，返回内容为“干扰素材”的合成音频流（见 T-A4）。 |
| 观测 | 页面初始化脚本只做**透传记录**：`getUserMedia`/`getDisplayMedia` 的调用、约束与返回轨道（类型、`readyState`、结束时间）、`MediaRecorder`/`RTCPeerConnection` 发送的轨道类型；每 100 ms 记录字幕区快照（时间、各条字幕文本、临时/定稿标记、样式）。Playwright 记录全部 HTTP 请求/响应与 WebSocket 收发帧（用于凭据扫描与画面数据检查，证据中只写统计与命中数）。 |
| 语音合成 | 本地 Piper TTS（pip 包 `piper-tts`，英语声音 `en_US-lessac-medium`，从 Hugging Face 下载模型），离线合成，不把文本发给第三方服务。 |
| 服务日志 | 只读平台提供的 `QA_SERVICE_LOGS_DIR`（`logs.jsonl`、`status.json`），等待 `logsReadAt` 晚于被检查操作结束后再判定；不自行读取集群。 |
| 时钟 | 素材页与应用页在同一浏览器进程、同一台机器上，统一使用 `Date.now()`。 |

## 3. 前置条件（平台提供）

- `AIDH_SERVICE_{N}_URL`：被测候选的 HTTPS 地址（选择规则见 T-A1）。
- `QA_CANDIDATE_SHA`、`QA_RESULT_PATH`、`QA_EVIDENCE_DIR`、`QA_SERVICE_LOGS_DIR`。
- 依赖 `test` 实例变量 `AIDH_DEP_*`（只用于凭据扫描的比对值与 IQA-114 的端点比对，不用于驱动应用）。
- 本交付不需要登录（A-06），**不需要测试身份机密**。若平台注入了任何 `AIDH_SECRET_*`，其值只作为 IQA-115、IQA-116 的扫描比对值，不写入证据。
- 可访问 npm、PyPI 与 Hugging Face 以安装 Playwright、Piper 与声音模型；Playwright 浏览器优先使用 `/ms-playwright` 中预装的版本。

| 编号 | 假设 |
| --- | --- |

## 6. 测试场景

执行分为 4 个互不干扰的会话组并行运行，每组使用独立的 Xvfb 显示与浏览器进程：

- **G-SYS**（系统声音主流程）：SYS-MAIN 会话（IQA-102～IQA-105、IQA-112、IQA-114、IQA-115、IQA-116、IQA-117 的取证）→ IQA-106 → IQA-107。
- **G-MIC**（麦克风回归）：IQA-113（M1～M12），同时为 IQA-114、IQA-115 提供麦克风模式的取证。
- **G-UI**（界面与错误路径，拆为两个子组并行）：G-UI1：IQA-120 → IQA-101 → IQA-108 → IQA-110 → IQA-122（含 IQA-119、IQA-117 小窗取证）；G-UI2（共享整个屏幕、不带声音的浏览器）：IQA-111 → IQA-121（1366×768 一轮同时作为 IQA-118 的取证）。
- **G-FF**（Firefox）：IQA-109、IQA-123。

每个场景开始前：新建浏览器上下文、打开被测地址；除 IQA-120 外，若出现首次引导则关闭它。失败场景保存截图、应用页控制台日志、媒体调用记录、字幕时间线、网络请求与 WebSocket 帧摘要（凭据与查询参数已遮蔽）。

### IQA-101 输入选择与只采集所选音源（AC-01）— 依赖假设 T-A2、T-A16、T-A17（G-UI）

- 前置：新上下文，Chromium 带假麦克风（MIC 素材）与标签页自动选择参数；打开页面。
- 操作与检查点：
  - c1 读取输入方式选项：恰有“麦克风”“系统声音”两项且默认选中“麦克风”。
  - c2 不做选择点击“开始”：`getUserMedia(audio)` 被调用、`getDisplayMedia` 调用 0 次；进入“正在听”。
  - c3 “正在听”时点击“系统声音”：选择不可操作（T-A16）。点击“停止”。
  - c4 改选“系统声音”并点击“开始”：`getDisplayMedia` 被调用（共享弹窗出现）；此次开始后 `getUserMedia` 调用 0 次，且无处于 live 的麦克风轨道。点击“停止”。
  - c5 刷新页面：输入方式回到“麦克风”。
- 证据：媒体调用记录、各步截图。

### IQA-102 系统声音出中文字幕且不混入麦克风（AC-02）— 依赖假设 T-A3、T-A4、T-A9（G-SYS / SYS-MAIN）

- 前置：素材页（标题 `QA-SHARE-TARGET`）已打开并加载 SYS 素材；应用页选择“系统声音”；`getUserMedia` 包装返回干扰素材（T-A4）。
- 操作：点击“开始”（自动共享素材标签页并带音频）→ 状态为“正在听”后开始播放 SYS → 播放结束并等待末尾静音结束。
- 检查点：
  - c1 共享返回的流含 ≥1 条音频轨道，状态 ≤ 20 s 进入“正在听”。
  - c2 SYS 6 句中至少 5 句产生了关键词命中的中文定稿字幕（含义细判在 IQA-104）。
  - c3 系统声音模式下 `getUserMedia` 调用 0 次；字幕中“香蕉”“大象”出现 0 次。
  - c4 共享期间素材页 `<audio>` 未被静音、音量未变、播放未中断；应用请求共享时未设置 `suppressLocalAudioPlayback: true`，音频轨道设置中该值不为 true（A-03）。
- 证据：字幕时间线、媒体调用记录、素材页播放状态记录、截图。

### IQA-103 系统声音流式时序（AC-03）— 依赖假设 T-A3、T-A8（G-SYS / SYS-MAIN 第 1 句）

- 前置：同 IQA-102；SYS 第 1 句时长 ≥ 8 s（脚本测量并写入证据）。
- 检查点：
  - c1 第 1 句的第一条中文字幕出现时间早于该句语音结束时间。
  - c2 首次出现后、语音结束前，该条字幕内容至少再变化一次。
  - c3 语音结束后 ≤ 15 s 内该条字幕成为定稿（不再改变，或带定稿标记），此后不再改变。
  - c4 同一条字幕处于临时状态与定稿状态时的可见样式签名（颜色、透明度、字形、字重、装饰、背景、边框、标记）不同。
  - c5 任一时刻字幕区最多一条临时字幕，且位于所有定稿字幕之后。
- 证据：带时间戳的字幕变化记录与句子起止时间对照表。

### IQA-104 自动识别语言、中文、含义一致（AC-04）— 依赖假设 T-A9、T-A11（G-SYS / SYS-MAIN）

- 检查点：
  - c1 页面（含引导关闭后）全程没有选择发言语言的控件（名称或选项含“语言/语种/English/英语/Language”的下拉框、单选、按钮）。
  - c2 每条定稿字幕为中文、不含英语原句（T-A11）。

  - c2 引导内容包含：选择输入方式（含“麦克风”与“系统声音”）、点击“开始”、选择共享内容并勾选共享音频（含“共享”与“音频”）、字号（含“字号”或“字体”）、字幕小窗（含“小窗”）。
  - c3 一次点击关闭；关闭后可直接点击“开始”进入“正在听”。
  - c4 刷新后 5 s 内引导不自动出现。
  - c5 入口可重新打开引导。
- 证据：截图、引导文字摘录。

### IQA-121 各尺寸布局（AC-11）— 依赖假设 T-A2、T-A3（G-UI）

- 前置：麦克风模式（合成麦克风播放 LOOP 内容）已产生多条字幕，含一条较长字幕。
- 操作：分别设置视口 1366×768、1440×900、1600×900、1920×1080、480×800；每个尺寸下依次：刷新（未开始）→ 麦克风模式开始并等到至少 1 条定稿字幕（正在听）→ 停止（已停止）→ 改选系统声音开始、共享不含声音（出错），四种状态各截图并测量。
- 检查点（每个尺寸）：
  - c1 `document.documentElement.scrollWidth ≤ clientWidth`（无横向滚动）。
  - c2 控制区四项可见、互不重叠（矩形两两无交叠），且可点击（`elementFromPoint` 命中自身）。
  - c3 字幕元素无水平溢出（`scrollWidth ≤ clientWidth + 1`），未被 `text-overflow`/`overflow:hidden` 截断。
- 证据：各尺寸截图、宽度测量记录。

### IQA-122 字幕小窗（支持的浏览器，AC-12，DD-101）— 依赖假设 T-A15、T-A3（G-UI）

- 前置：Chromium（有界面），共享素材页，系统声音“正在听”，素材页循环播放 LOOP。
- 操作：a) 点击含“字幕小窗”的按钮；播放期间每 1 s 同时读取主页面与小窗字幕共 20 次；关闭小窗，继续 15 s；再次弹出。b) 停止后改选“麦克风”（合成麦克风）开始，弹出小窗，等待 2 条定稿。
- 检查点：
  - c1 点击后 ≤ 5 s 出现独立窗口（T-A15），不是页面内浮层。
  - c2 小窗定稿字幕序列与主页面一致（内容与顺序），临时字幕差异仅允许在 0.5 s 内消失；小窗显示状态文字“正在听”。
  - c3 关闭小窗后主页面 15 s 内仍有字幕新增或更新、状态保持“正在听”、共享轨道 live。
  - c4 再次弹出后小窗显示与主页面相同的当前全部字幕。
  - c5 麦克风模式下按钮可用，小窗与主页面字幕一致。
  - 不判定“悬浮在全屏视频/会议软件之上可见”（DD-101）。
- 证据：同一时刻的主页面与小窗字幕对比、窗口记录、截图。

### IQA-123 字幕小窗（不支持的浏览器，AC-12）— 依赖假设 T-A5（G-FF）

- 前置：Playwright Firefox，假麦克风已授权。
- 检查点：
  - c1 “字幕小窗”按钮可见但不可用（禁用，或点击后无新窗口）。
  - c2 按钮附近（同一控制区或其提示内）可见中文原因（含“不支持”）与支持的浏览器（含 Chrome 或 Edge）。
  - c3 麦克风模式点击“开始”进入“正在听”，播放 ONE 后出现中文字幕（与 IQA-104 同口径）。
- 证据：浏览器版本、截图。
