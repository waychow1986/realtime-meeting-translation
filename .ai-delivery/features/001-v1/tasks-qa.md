# 独立测试计划 · 企业实时翻译（会议中文字幕）

> 依据：已确认的意图 v2（AC-01～AC-09、A-01～A-06、Q-01～Q-05 人工答案）与 `spec.md`（FR-001～FR-022、E-1～E-3、验收场景 IQA-001～IQA-011、PQ-001 人工答案）。
> 本计划不依据实现代码；页面结构、接口路径、字段名等实现细节未知，均按下文“假设”从候选实际返回的内容中读取。
> 执行脚本：`runtime/qa-run.sh`（本 Feature 目录下）。不声明分阶段执行（不需要重新部署前后对比），因此没有 `runtime/qa-phases.json`。

## 1. 被测对象与执行环境

| 项 | 内容 |
| --- | --- |
| 被测候选 | 平台部署到测试环境的候选，提交号 `QA_CANDIDATE_SHA`；访问地址取自 `AIDH_SERVICE_{N}_URL`。存在多个服务时，取对根路径 `/` 返回 HTML 页面的那个（名称含 WEB/APP/UI/FRONTEND 的优先）。 |
| 依赖 | 真实测试环境中的 Azure Foundry 语音转文字服务与 Azure Foundry 大模型部署，接入信息取自平台注入的 `AIDH_DEP_{N}_*`（`test` 实例）。不使用任何模拟服务；`scenarios[].externalServices` 只写实际依赖名。 |
| 浏览器 | Playwright 驱动的 Chromium 新版无头模式（`channel: chromium`，与桌面 Chrome/Edge 同内核），每个场景使用全新、无插件、无缓存的浏览器配置。 |
| 麦克风输入 | Chromium 的虚拟麦克风设备：`--use-fake-device-for-media-stream --use-file-for-fake-audio-capture=<wav>%noloop`。页面每次调用 `getUserMedia` 打开麦克风时，WAV 从头开始作为麦克风输入实时送入，播完后为静音（规格“测试语音……作为麦克风设备的虚拟音频输入均可”）。麦克风权限通过浏览器权限授予 / 不授予来模拟“允许 / 拒绝”。 |
| 测试素材 | 脚本内用离线语音合成（piper-tts，en_US 语音）合成英语句子；若离线合成不可用，退回到用语音依赖的语音合成能力合成。素材只含英语，不含中文发言（PQ-001）。 |
| 时钟 | 页面内注入的观测脚本用同一页面时钟（`Date.now()`）记录：`getUserMedia` 成功返回的时刻（= 素材开始送入的时刻 t0）、字幕区域每次变化的时刻与内容、轨道停止的时刻。每句语音的起止时间 = t0 + 合成时得到的句子偏移。 |
| 运行限制 | 整个脚本 15 分钟内完成；脚本只写工作目录、`QA_RESULT_PATH`、`QA_EVIDENCE_DIR`；不关闭 TLS 校验；证据中不写入任何凭据值。 |

素材文件：

- `main.wav`：S1，静音 2.5 秒，S2～S6（每句后静音 2.5 秒）。用于 IQA-001～IQA-005、IQA-007～IQA-009。
- `stop.wav`：同 `main.wav` 的句序，用于 IQA-006（停止点之后仍有 ≥ 30 秒的英语语音）。

## 3. 采用的假设（规格未给出的参数与实现细节）

## 4. 通用检查（每个浏览器场景都执行）

- 打开候选地址后页面返回 2xx 且为 HTML；候选不可达、DNS/TLS 失败时整体结果为环境问题：`passed=false`，`defects`、`testGaps` 为空，诊断写入证据。
- 证据：每个场景保存页面截图（开始前、翻译中、停止后）、录屏（webm）、字幕变化时间线（`*-timeline.json`：时刻、字幕行）、控制台日志、网络请求清单（只含方法、地址主机与路径、状态码、实时连接帧数量与大小；不含请求头值与正文，避免凭据进入证据）、`getUserMedia` 调用与轨道状态记录。

## 5. 测试场景

场景编号只用规格中的验收场景编号；边界与错误情况写成该场景的检查点。浏览器运行分 4 次：主运行（`main.wav`，IQA-001～005 共用，同时为 IQA-007～009 采集数据）、停止运行（IQA-006）、拒绝权限运行（IQA-010）、刷新与多页面运行（IQA-011）。

### IQA-001 打开即用（AC-01；FR-001、002、003、005）

- 前置条件：全新无插件 Chromium 配置；已授予麦克风权限；虚拟麦克风为 `main.wav`。
- 操作：打开候选地址 → 截图 → 点击“开始” → 等待素材播完并静音 ≥ 15 秒 → 点击“停止”。
- 检查点与预期：
  1. 无安装/插件要求：页面加载过程中没有跳转到其它域名的登录页（如 `login.microsoftonline.com`），页面中没有密码输入框，没有出现要求下载/安装应用或扩展的文字（“安装”“下载客户端”“扩展程序”“插件”）。
  2. 界面为中文：开始按钮、停止按钮的名称含汉字；页面可见文字中汉字数多于拉丁字母单词数（字幕以外）。
  3. 无语言选择控件：页面中没有 `select`、`combobox`、`listbox`、`radio` 控件，也没有任何可见控件文字含“语言/Language/英语/日语/English”等语言名（开始前、翻译中都检查）。
  4. 状态切换（依赖假设 QA-A2）：开始前为“未开始/已停止”类状态；开始后 10 秒内为“翻译中”类状态；停止后 3 秒内为“已停止”类状态。
  5. 出现中文字幕：翻译中出现至少一条字幕行。
- 证据：`iqa-main-*.png`、`iqa-main.webm`、`iqa-main-timeline.json`、`browser-info.json`（浏览器版本、扩展为空）。

### IQA-002 流式字幕时序（AC-02；FR-006、007）——依赖假设 QA-A3、QA-A5

- 前置条件：主运行已开始翻译；S1 合成时长 ≥ 8 秒。
- 操作：S1 作为素材第一句送入。
- 检查点与预期：
  1. 首条字幕早于句末：第一条字幕行出现时刻 < S1 结束时刻。
  2. 句中持续更新：首条字幕出现后、S1 结束前，字幕内容至少再变化 1 次（共 ≥ 2 个不同的字幕状态）。
  3. 句末定稿：S1 结束后，最终字幕中含 S1 的锚点，且该句定稿文字在 S3 的锚点出现后不再改变。
  4. 反例判定：若所有字幕变化都发生在 S1 结束之后（整句说完才一次性出现），判为失败。
- 证据：`iqa-main-timeline.json`、`iqa-002-timing.json`（S1 起止时刻、各次字幕变化时刻）。

### IQA-003 无需选择语言（AC-03；FR-003、008）

- 前置条件：新打开页面，不做任何设置。
- 操作：主运行中直接点击“开始”，送入英语多句素材 S1～S6。
- 检查点与预期：
  1. 全过程无语言选择：同 IQA-001 检查点 3（开始前、翻译中、停止后）。
  2. 不需要额外操作：点击“开始”之后，测试没有进行任何其它页面操作，仍产生字幕。
  3. 每句产生中文字幕：最终字幕中 S1～S6 的唯一锚点全部出现。
- 自动识别语言的服务侧证据由 IQA-007 检查点 3 提供（AC-03 由 IQA-003 与 IQA-007 共同覆盖）。

### IQA-004 中文且与发言含义一致（AC-04；FR-009、010）——依赖假设 QA-A3、QA-A6

- 前置条件：主运行已结束（素材播完并静音 ≥ 15 秒）。
- 操作：取定稿字幕，按唯一锚点把字幕切分归属到 S1～S6，逐句与第 2 节关键要素比对。
- 检查点与预期：
  1. 每句定稿字幕为中文：归属到每句的字幕文字中汉字占比 ≥ 70%（人名“Michael”、“Q3”之类的保留拉丁写法除外）。
  2. 不显示英语原文：页面可见文字中不出现任何一句素材原文的连续 4 个英语单词。
  3. 逐句含义一致：每句的关键要素全部命中；任一句缺失即失败，并在证据中列出缺失要素。
- 证据：`iqa-004-comparison.json`（逐句：参考译文、定稿字幕、命中/缺失要素）。

### IQA-005 多句顺序不重不漏（AC-05；FR-007、011、012）——依赖假设 QA-A3

- 前置条件：同 IQA-004。
- 检查点与预期：
  1. 不遗漏：S1～S6 的唯一锚点在定稿字幕中都出现。
  2. 不重复：每个唯一锚点在定稿字幕中恰好出现 1 次。
  3. 顺序：锚点首次出现的位置按 S1→S6 递增。
  4. 条数：若字幕按句分行（字幕行数 > 1），定稿字幕行数 = 6；若全部字幕在同一行内连续排版，只按检查点 1～3 判定，并在观察中注明。
  5. 定稿不变：S1～S4 每句定稿文字在其后第 2 句的锚点出现时已与最终一致（之后不再改变）。
  6. 静音无新字幕：素材结束 6 秒后到点击“停止”前（≥ 9 秒静音），字幕区域没有任何变化。
- 证据：`iqa-005-alignment.json`（锚点位置、字幕行与句子对应表）、`iqa-main-timeline.json`。

### IQA-006 停止后不再采集、不再出字幕（AC-06；FR-013、014、015）——依赖假设 QA-A1、QA-A2、QA-A4

- 前置条件：全新页面，虚拟麦克风为 `stop.wav`，已开始翻译。
- 操作：在 S2 播放到一半时点击“停止”；之后等待 32 秒（若候选未真正停止麦克风，`stop.wav` 在此期间继续送入 ≥ 30 秒英语语音）；然后再次点击“开始”，等待新字幕（最长 40 秒），再停止。
- 检查点与预期：
  1. 停止前已有字幕（S1 已出现字幕）。
  2. 停止后 2 秒内全部麦克风轨道为 `ended`，状态为“已停止”类。
  3. 停止后不再发送音频：停止 2 秒后至再次开始前，页面没有向任何实时连接发送 > 1 KB 的数据帧，也没有新的 `getUserMedia` 调用。
  4. 停止时句子正在处理的边界：以停止后 1 秒时的字幕快照为基准，之后 31 秒内字幕区域无任何新增或修改（含停止时未定稿的那句）。
  5. 停止前字幕保留：停止前最后一次快照中已含锚点的定稿字幕行在停止后仍在。
  6. 再次开始：状态回到“翻译中”；新字幕出现在已有字幕之后（已有字幕行保持不变并位于前面，新出现的 S1 锚点位于原有文字之后）。
- 证据：`iqa-006-timeline.json`、`iqa-006-*.png`、`iqa-006.webm`、`iqa-006-network.json`（停止前后实时连接帧计数）。

### IQA-007 真实服务与配置（AC-07；FR-018、019、020）——依赖假设 QA-A7

- 前置条件：主运行（IQA-002、IQA-005）已执行并记录起止时间窗；依赖 `test` 实例接入信息已注入。
- 操作：读取依赖注入信息与 Azure 资源信息；分析主运行中浏览器可见的实时连接；在时间窗结束后读取 Azure Monitor 指标；用依赖接入信息直接调用依赖做配置核对。
- 检查点与预期：
  1. 真实依赖：语音依赖与大模型依赖的地址为 Azure 服务域名（`*.cognitiveservices.azure.com`、`*.api.cognitive.microsoft.com`、`*.services.ai.azure.com`、`*.openai.azure.com`、`*.speech.microsoft.com`），且可用注入的接入信息成功访问（语音：签发短时令牌或资源信息可读；模型：一次中文翻译调用成功）；不是本机/模拟地址。
  2. 实时（流式）识别：浏览器可见的语音服务实时连接中出现中间识别结果（如 `speech.hypothesis`），或 Azure Monitor 中语音资源在时间窗内有实时会话/音频时长指标 > 0；并且 IQA-002 证明字幕随发言流式更新。
  3. 语言自动识别：浏览器可见的语音连接配置/结果中出现语言识别配置或识别出的语言（如 `languageId`/`LanguageDetection`/`PrimaryLanguage`/`lidEnabled`），或候选诊断接口声明开启语言自动识别；同时 IQA-003 证明用户未选择语言。
  4. 大模型完成翻译：Azure Monitor 中模型资源在时间窗内的请求/令牌指标 > 0，或浏览器可见请求直接发往模型部署。
  5. 模型与 reasoning：模型部署（注入的部署名）对应的模型为 gpt-sol-6.1；若不是，记录测试环境中 gpt-sol-6.1 是否可用的证据（A-05）。reasoning 关闭的证据：模型本身不产生推理令牌（直接调用返回 `reasoning_tokens` 为 0），或候选诊断接口声明关闭 reasoning；直接用 `reasoning_effort: none` 调用该部署成功作为“可关闭”的补充证据。
- 任一项拿不到证据时记为测试缺口（说明缺哪类证据）；拿到证据但与要求不符（如走模拟服务、未开启语言识别、模型开启 reasoning）记为产品缺陷。
- 证据：`iqa-007-services.json`（资源类型、域名、部署与模型名、指标值；不含密钥与客户内容）。

## 7. 结果归类

- 产品缺陷（`defects`）：场景执行完成、证据显示未达到上述预期。
- 测试缺口（`testGaps`）：脚本自身未能完成验证（例如页面上找不到开始按钮导致无法驱动、服务侧证据或服务端日志无从获取、素材合成失败）；写明缺哪类证据、依据哪条假设。
- 环境或平台问题：候选地址或依赖不可达、DNS/TLS 失败、浏览器无法启动等；`passed=false`，`defects`、`testGaps` 为空，诊断写入 `evidence`。
- 总体 `passed=true` 仅当 IQA-001～IQA-011 全部通过、`defects` 与 `testGaps` 都为空。
- 脚本在写出有效结果后以 0 退出（即使发现缺陷）。
