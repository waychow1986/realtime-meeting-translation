# 企业实时翻译 · 会议中文字幕 业务意图

## 摘要

开会时发言人可能是外国人，与会者需要实时看懂发言。本次交付一个通过浏览器打开的 Web 应用：自动检测发言语言，把其它语言的语音**实时、流式**翻译成**中文字幕**，体验“类似 Azure 语音转文字的实时翻译功能或者 Teams 的实时字幕功能”。

## 要解决的问题

会议中外籍发言人使用外语发言，中文与会者无法及时理解。需要“提供实时语音转文字的翻译功能，主要是将其它语言的语音翻译成中文字幕”，并且“要求实现流式翻译”，“语音需要支持自动检测，然后翻译成中文字幕”（需求原文第 1、2、4 条）。

## 受影响用户

- 参加会议、需要看中文字幕的与会者（打开 Web 应用的人）。
- 会议中的发言人（其语音被识别与翻译；可能是外国人）。

## 范围

### 范围内

- **INT-001** 实时语音转文字并翻译成中文字幕（原文第 1 条）。
- **INT-002** 流式翻译：发言进行中即持续呈现字幕，类似 Azure 语音转文字实时翻译或 Teams 实时字幕（原文第 2 条）。
- **INT-003** 语音语言自动检测，无需与会者预先指定发言语言（原文第 4 条）。
- **INT-004** 以 Web App 形式提供，通过浏览器打开服务（技术偏好第 5 条）。
- **INT-005** 使用场景为会议（原文第 3 条）。

### 不做的事

- 不做桌面应用（技术偏好第 5 条明确要求）。
- 不翻译成中文以外的目标语言。
- 不提供会议录音、字幕历史保存、导出或会议纪要生成（需求未要求；且宪章要求不记录客户内容）。
- 不做与 Teams 等会议软件的插件或集成，只借鉴其实时字幕的体验。
- 不提供语音合成（把译文读出来）。

## 客户明确的技术约束（原样记录）

1. 使用 Azure Foundry 中的语音转文字服务（STT）+ Azure Foundry 中的大模型实现整体功能。
2. 前者实现语音转文字，大模型实现将文字翻译成中文。
3. 前者要求开启实时听录功能即流式、开启语言自动识别，后者要求关闭 reasoning。
4. 大模型可以选择 gpt-sol-6.1。
5. 要求呈现为 web app 的形式，也就是说通过浏览器来打开服务，不要做成桌面 app。
6. 如果所需要的技术组件或者模型不存在，允许在测试环境中创建，或者复用已有测试环境的技术能力。

宪章约束：凭据保留在服务端；不记录 secret 或客户内容；每项用户可见能力都有可独立执行的验收场景；外部集成须针对真实测试服务验证，Mock 不能替代验收证据。

## 验收标准

- **AC-01** 用户在桌面浏览器中打开应用地址即可使用全部功能，不需要安装任何桌面应用或浏览器插件。
- **AC-02** 用户启动翻译后，有人用外语（如英语）连续说一句较长的话时，中文字幕在这句话说完之前就开始出现，并随发言持续更新（流式），而不是整句说完后才一次性出现。
- **AC-03** 用户启动翻译前后都无需选择发言语言；同一次使用中发言语言从英语切换为另一种支持的外语（如日语）后，字幕仍持续输出对应发言的中文翻译。
- **AC-04** 字幕以中文呈现，且字幕内容与发言含义一致（对已知外语测试语音，译文表达的意思与参考中文译文一致）。
- **AC-05** 连续多句发言时，中文字幕按发言先后顺序呈现，最终定稿的字幕不重复、不遗漏句子。
- **AC-06** 用户可以开始和停止翻译；停止后不再采集音频，也不再出现新的字幕。
- **AC-07** 语音转文字由 Azure Foundry 语音服务以实时（流式）识别并开启语言自动识别完成；翻译由 Azure Foundry 中的大模型完成且关闭 reasoning；以上均在真实测试环境服务上验证。
- **AC-08** 浏览器可见的页面源码、脚本与网络请求中不出现 Azure 服务的密钥或其它长期凭据。
- **AC-09** 应用的服务端日志中不出现发言识别文本或中文译文内容。

## 假设

- A-01 目标用户使用桌面版主流浏览器（Chrome / Edge 最新版）；移动端浏览器不在本次验收范围。
- A-02 一个浏览器页面显示本页面采集到的语音的字幕；不做“一人采集、多人订阅同一字幕”的共享广播。
- A-03 发言为中文时不需要翻译，按原样以中文字幕显示（若被识别）。
- A-04 字幕仅在使用期间显示于页面，刷新或关闭页面后不保留。
- A-05 部署与验证在测试环境中进行；所需组件或模型（含 gpt-sol-6.1）不存在时按约束 6 在测试环境创建或复用。若 gpt-sol-6.1 在测试环境不可用，选用 Azure Foundry 中可关闭 reasoning 的其它大模型（“可以选择”视为偏好而非硬性要求）。
- A-06 界面语言为中文。

## 待澄清问题（由业务负责人在确认意图时回答）

按影响大小排序：

- [ ] **Q-01 会议语音从哪里采集？**（出处：需求原文第 3 条“主要是开会时候使用”；未说明是线下会议室还是线上会议）
  - **推荐**：通过浏览器采集本机麦克风（适用于线下会议室或外放的线上会议）。
  - 备选 B：采集浏览器标签页/系统音频（直接获取 Teams 等线上会议的声音）。
  - 备选 C：两者都支持，由用户选择音源。
- [ ] **Q-02 自动检测需要覆盖哪些发言语言？**（出处：需求原文第 1、4 条“其它语言”“自动检测”；语音服务的连续语言自动识别通常需限定候选语言数量）
  - **推荐**：英语、日语、韩语、法语、德语、西班牙语（另含中文以便原样显示）。
  - 备选 B：仅英语（另含中文）。
  - 备选 C：由业务方提供指定语言清单。
- [ ] **Q-03 “流式翻译”要求到什么程度？**（出处：需求原文第 2 条“类似 Azure 语音转文字的实时翻译功能或者 teams 的实时字幕功能”）
  - **推荐**：发言进行中即显示并持续更新的中文译文（临时译文），句子结束后替换为定稿译文。
  - 备选 B：发言进行中实时显示原文识别结果，每句结束后立刻显示该句中文译文。
- [ ] **Q-04 字幕是否同时显示原文？**（出处：需求原文第 1 条“翻译成中文字幕”）
  - **推荐**：中文字幕为主，同时以较小字号显示原文，便于对照。
  - 备选 B：仅显示中文字幕。
- [ ] **Q-05 谁可以访问该 Web 应用？**（出处：需求标题“企业实时翻译”；宪章“安全与隐私”）
  - **推荐**：本次在测试环境中凭访问地址即可使用，不做登录。
  - 备选 B：需使用企业账号（Microsoft Entra ID）登录后才能使用。
