# 企业实时翻译 · 会议中文字幕 产品规格

> 依据：已确认的意图 v2（交付输入，含 Q-01～Q-05 的人工答案）与需求原文 `request.json`。
> 说明：仓库中的 `intent.md` 正文早于意图 v2，其中 AC-03 的写法（“中途切换为日语”）与假设 A-03 已被意图 v2 取代；本规格以意图 v2 为准。
> 本规格只描述“做成什么样”，不做技术选择；客户在需求原文中明确指定的服务约束按原样作为约束引用（INT-004、约束 1～6）。

## 产品目标与边界

| 意图范围 | 产品行为边界 |
| --- | --- |
| INT-001 实时语音转文字并翻译成中文字幕 | 采集本机麦克风中的外语发言，识别为文字并以中文字幕显示在页面上。 |
| INT-002 流式翻译 | 发言进行中即显示并持续更新中文临时字幕，句子结束后替换为该句定稿字幕（Q-03 答案）。 |
| INT-003 语言自动检测 | 用户在任何时候都不选择发言语言；发言语言由语音服务自动识别（Q-02 答案）。 |
| INT-004 Web App | 用户通过桌面浏览器打开地址使用，不安装桌面应用或浏览器插件。 |
| INT-005 会议场景 | 作为独立的字幕页面使用（线下会议室或外放的线上会议），不集成会议软件（Q-01 答案）。 |

范围外（意图“不做的事”）：桌面应用；中文以外的目标语言；录音、字幕历史保存、导出、会议纪要；与 Teams 等会议软件的插件或集成；语音合成；多人订阅同一字幕的共享广播（A-02）；移动端浏览器（A-01）；登录与账号管理（Q-05 答案）。

## 参与者与权限

| 参与者 | 说明 | 权限 |
| --- | --- | --- |
| 字幕使用者 | 打开 Web 应用查看中文字幕的与会者。 | 凭访问地址即可使用全部功能，不需要登录（Q-05）。只能看到自己页面采集到的语音所产生的字幕（A-02）。 |
| 发言人 | 会议中的发言者，可能是外国人。 | 不操作应用；其语音经使用者本机麦克风被采集。 |
| 测试环境运维者 | 部署与配置测试环境的人员。 | 唯一可接触 Azure 服务凭据的角色；凭据不向字幕使用者的浏览器暴露（AC-08）。 |

数据访问要求：

- 字幕使用者的浏览器在任何时候都不获得 Azure 服务的密钥或其它长期凭据（AC-08）。
- 发言音频、识别文本与中文译文只用于即时生成字幕，不被保存，不写入服务端日志（AC-09、非目标“不提供录音/历史保存”）。

## 用户故事

### US-001 打开即用（P1）
作为与会者，我希望在桌面浏览器中打开一个地址就能使用字幕功能，以便不用安装任何软件。引用 INT-004；覆盖 AC-01。

### US-002 外语发言实时看到中文字幕（P1）
作为不懂外语的与会者，我希望外籍发言人说话时，中文字幕在其说话过程中就出现并持续更新，句子说完后定稿，以便我及时理解发言。引用 INT-001、INT-002、INT-005；覆盖 AC-02、AC-04、AC-05。

### US-003 无需选择语言（P1）
作为与会者，我希望不用事先选择发言语言，以便直接开始使用。引用 INT-003；覆盖 AC-03。

### US-004 开始与停止（P1）
作为与会者，我希望可以随时开始和停止翻译，停止后麦克风不再被使用、也不再出现新字幕，以便控制何时采集声音。引用 INT-001；覆盖 AC-06。

### US-005 凭据与内容保护（P1）
作为企业，我希望服务凭据不出现在浏览器中，发言内容与译文不出现在服务端日志中，以便符合宪章“安全与隐私”。覆盖 AC-08、AC-09。

### US-006 使用客户指定的服务（P1）
作为客户，我希望语音识别使用 Azure Foundry 语音服务的实时识别与语言自动识别，翻译使用 Azure Foundry 大模型且关闭 reasoning，并在真实测试环境中验证。引用约束 1～3、6；覆盖 AC-07。

## 功能需求

### 访问与界面

- **FR-001**：使用者在桌面版 Chrome 或 Edge 最新版中打开应用地址后，无需安装任何桌面应用、浏览器插件，也无需登录，即可使用本规格中的全部功能。（AC-01；INT-004；Q-05；A-01）
- **FR-002**：页面界面文字（按钮、状态、提示、错误信息）为中文。（A-06）
- **FR-003**：页面上不存在任何选择或指定发言语言的控件，开始翻译前后都不要求使用者提供发言语言。（AC-03；INT-003）

### 开始翻译与音频来源

- **FR-004**：页面提供“开始”操作。使用者触发后，页面通过浏览器请求并使用本机麦克风作为唯一音源；不采集浏览器标签页或系统音频。（AC-06；Q-01）
- **FR-005**：页面始终显示当前状态，至少区分“未开始/已停止”和“翻译中”两种状态，状态与实际是否在采集音频一致。（AC-06）

### 字幕生成与呈现

- **FR-006**：翻译中，当发言人说出一句外语时，页面在这句话说完之前就显示该句的中文临时字幕，并在说话过程中随发言内容更新该临时字幕。（AC-02；INT-002；Q-03）
- **FR-007**：一句话说完后，该句的临时字幕被替换为该句的中文定稿字幕；定稿后该句字幕不再改变。（AC-02、AC-05；Q-03）
- **FR-008**：发言语言由服务自动识别；对英语发言，字幕输出对应发言的中文翻译。同一次使用中途切换发言语言不作要求。（AC-03；Q-02）
- **FR-009**：字幕只显示中文译文，不显示发言原文。（AC-04；Q-04）
- **FR-010**：每句定稿字幕表达的意思与该句发言含义一致。（AC-04）
- **FR-011**：连续多句发言时，定稿字幕按发言先后顺序排列；每句发言恰好对应一条定稿字幕，不重复、不遗漏。（AC-05）
- **FR-012**：没有人发言（静音或仅环境噪声）时，不产生新的字幕内容。（AC-05 推论：不产生不对应发言的字幕）

### 停止翻译

- **FR-013**：页面提供“停止”操作。使用者触发后，页面立即停止使用麦克风（浏览器的麦克风使用指示随之消失），状态变为“已停止”。（AC-06）
- **FR-014**：停止之后，字幕区域不再出现新的字幕，也不再修改已有字幕（包括停止时尚未定稿、仍在处理中的内容）；停止前已显示的字幕保留在页面上供查看。（AC-06；A-04）
- **FR-015**：停止后使用者可以再次“开始”，新的字幕接在已有字幕之后出现。（AC-06）

### 数据与会话

- **FR-016**：字幕只在当前页面使用期间显示；刷新或关闭页面后不保留，应用不提供字幕历史、导出或录音。（A-04；非目标）
- **FR-017**：每个浏览器页面只显示本页面采集到的语音所产生的字幕；同时打开的其它页面互不显示对方的字幕。（A-02）

### 服务约束（客户指定）

- **FR-018**：语音转文字由 Azure Foundry 中的语音转文字服务完成，且使用其实时（流式）识别与语言自动识别能力。（AC-07；约束 1～3）
- **FR-019**：识别文字到中文的翻译由 Azure Foundry 中的大模型完成，且调用时关闭 reasoning；优先使用 gpt-sol-6.1，若其在测试环境不可用，使用 Azure Foundry 中可关闭 reasoning 的其它大模型。（AC-07；约束 2～4；A-05）
- **FR-020**：以上服务均为真实测试环境中的服务；所需组件或模型不存在时可在测试环境中创建或复用。（AC-07；约束 6）

### 安全与隐私

- **FR-021**：浏览器可见的页面源码、脚本以及页面发出和接收的所有网络请求（含实时连接中的消息）中，不出现 Azure 服务的密钥或其它长期凭据。（AC-08；宪章“安全与隐私”）
- **FR-022**：应用的服务端日志中不出现发言识别文本或中文译文内容，也不出现任何 secret。（AC-09；宪章“安全与隐私”）

## 产品质量要求

当前没有获批准的额外质量要求（时延数值、可用率、并发人数、可访问性等级等均未获批准）。流式性的判定只采用 AC-02 给出的相对时序：字幕在该句说完之前出现并持续更新。

## 领域术语

| 术语 | 含义 |
| --- | --- |
| 一句话 / 句子 | 发言人连续说出、以自然停顿结束的一段话；以测试素材中预先划分的句子为准。 |
| 临时字幕 | 一句话尚未说完时显示的中文译文，会随发言更新。 |
| 定稿字幕 | 一句话说完后替换临时字幕的最终中文译文，此后不再改变。 |
| 翻译中 | 使用者已“开始”且尚未“停止”的状态，此时麦克风被采集。 |
| 长期凭据 | 非一次性、非短时有效的访问凭据，如服务密钥、连接字符串、长期访问令牌。 |
| 客户内容 | 发言音频、识别文本与中文译文。 |

## 前置条件与触发条件

- 前置条件：测试环境已部署本应用，并已连接真实的 Azure Foundry 语音服务与大模型；使用者使用桌面版 Chrome 或 Edge 最新版；电脑有可用麦克风。
- 触发条件：使用者点击“开始”并在浏览器中允许麦克风权限后进入“翻译中”；点击“停止”、刷新或关闭页面后结束。

## 行为模型

### US-001 打开应用
- 正常：使用者在 Chrome/Edge 中打开地址 → 页面以中文显示，状态为“未开始”，有“开始”操作，无语言选择控件，无登录要求。（FR-001～FR-003、FR-005）
- 边界：浏览器未安装任何插件时功能完整可用。（FR-001）

### US-002 外语发言实时出现中文字幕
- 正常：翻译中，发言人用英语说一句较长的话 → 说话过程中出现该句中文临时字幕并随发言更新 → 说完后替换为定稿字幕。（FR-006、FR-007、FR-009、FR-010）
- 连续多句：下一句的临时字幕出现在已定稿字幕之后；所有定稿字幕按发言顺序排列，句句对应。（FR-011）
- 静音：无人发言期间不出现新字幕。（FR-012）
- 中文发言：意图 v2 未规定，见 PQ-001，未决前不作为验收内容。

### US-003 无需选择语言
- 正常：不做任何语言设置，直接开始 → 英语发言产生中文字幕。（FR-003、FR-008）
- 范围外：同一次使用中途切换发言语言不作要求。（Q-02）

### US-004 开始与停止
- 正常：开始 → 浏览器请求麦克风权限 → 允许后状态为“翻译中”，浏览器显示麦克风使用中。停止 → 麦克风使用指示消失，状态为“已停止”，此后字幕区域不再变化。（FR-004、FR-005、FR-013、FR-014）
- 替代：停止后再次开始 → 新字幕接在已有字幕之后。（FR-015）
- 边界：停止时恰好有一句话正在说或正在翻译 → 停止后这句话不再出现新的字幕或修改。（FR-014）
- 边界：刷新或关闭页面 → 麦克风停止使用，字幕清空且不可恢复。（FR-016）
- 错误：见“错误与恢复行为”。

### US-005 凭据与内容保护
- 正常：在整个使用过程中，浏览器可见内容不含长期凭据；服务端日志不含识别文本与译文。（FR-021、FR-022）

### US-006 使用客户指定的服务
- 正常：字幕由真实测试环境中的 Azure Foundry 语音服务（实时识别、语言自动识别）与 Azure Foundry 大模型（关闭 reasoning）产生。（FR-018～FR-020）

## 业务状态、业务数据规则与不变量

状态：`未开始` →（开始且允许麦克风）→ `翻译中` →（停止 / 错误）→ `已停止` →（开始）→ `翻译中`。

不变量：

1. 麦克风仅在 `翻译中` 被使用；`未开始`、`已停止` 状态下浏览器不显示麦克风使用中。（FR-013）
2. 不处于 `翻译中` 时，字幕区域不发生任何变化。（FR-014）
3. 任一时刻最多存在一条临时字幕，且位于所有定稿字幕之后。（FR-007、FR-011）
4. 定稿字幕一经出现不再改变、不被移除（刷新/关闭页面除外）；顺序与发言顺序一致，与发言句子一一对应。（FR-007、FR-011）
5. 字幕区域只包含中文译文，不包含发言原文。（FR-009）
6. 客户内容不被保存、不写入服务端日志；浏览器不持有长期凭据。（FR-016、FR-021、FR-022）

## 错误与恢复行为

| 情况 | 用户可见行为 | 恢复 |
| --- | --- | --- |
| E-1 使用者拒绝麦克风权限，或电脑没有可用麦克风 | 页面以中文提示无法使用麦克风及原因类别（被拒绝 / 无设备），状态保持或回到“未开始/已停止”，不出现字幕。 | 使用者在浏览器中允许权限或接入麦克风后，再次点击“开始”即可。 |
| E-2 语音识别或翻译服务不可用、连接中断 | 页面以中文提示翻译已中断，状态变为“已停止”，麦克风停止使用；已显示的定稿字幕保留。 | 使用者再次点击“开始”；服务恢复后可继续产生字幕。 |
| E-3 某一句翻译失败而服务整体可用 | 该句不显示错误的或非中文的内容；后续句子继续正常产生字幕。 | 无需使用者操作。 |

错误提示中不包含凭据、服务内部地址或客户内容。（FR-021、FR-022）

E-1、E-2 的提示行为是本规格为“开始/停止”补全的最小合理默认，不改变意图范围；E-3 下该句缺失属于异常情况，不计入 AC-05 正常验收。

## 安全、隐私与可访问性行为

- 凭据：浏览器可见内容（页面源码、脚本、全部网络请求与实时连接消息）不含 Azure 服务密钥、连接字符串或其它长期凭据。短时有效、仅限本次使用的访问令牌不属于 AC-08 所禁止的长期凭据。（FR-021；AC-08；宪章“凭据保留在服务端”）
- 客户内容：识别文本与译文不写入服务端日志；音频、识别文本与译文不被保存。（FR-016、FR-022；AC-09；宪章“绝不记录 secret 或客户内容”）
- 访问控制：本次不做登录，凭访问地址即可使用（Q-05 人工答案）。
- 可访问性：当前没有获批准的可访问性等级要求。

## 性能、可靠性与其他质量边界

当前没有获批准的额外要求（不设定时延数值、可用率、并发、会话时长上限）。流式时序只按 AC-02 的相对关系判定（见 IQA-002）。

## 成功标准

- **SC-001**：在桌面版 Chrome/Edge 中，不安装任何软件或插件、不登录，即可完成“开始 → 看到中文字幕 → 停止”的完整流程。（AC-01）
- **SC-002**：对一句较长的英语发言，该句的中文字幕在说完之前出现，并在说完之前至少更新一次，说完后定稿。（AC-02）
- **SC-003**：全程未选择发言语言，英语发言产生中文字幕。（AC-03）
- **SC-004**：对已知英语测试语音，每句定稿字幕为中文，且意思与参考中文译文一致。（AC-04）
- **SC-005**：多句发言的定稿字幕数量、顺序与发言句子一一对应，无重复、无遗漏。（AC-05）
- **SC-006**：停止后麦克风不再被使用，字幕区域不再变化。（AC-06）
- **SC-007**：字幕由真实测试环境中开启实时识别与语言自动识别的 Azure Foundry 语音服务，以及关闭 reasoning 的 Azure Foundry 大模型产生。（AC-07）
- **SC-008**：浏览器可见内容中检出长期凭据的数量为 0。（AC-08）
- **SC-009**：服务端日志中检出测试发言识别文本或译文的数量为 0。（AC-09）

## 验收场景

通用约定：

- 环境：真实测试环境中部署的应用，连接真实的 Azure Foundry 语音服务与大模型；不得使用 Mock 作为验收证据（宪章“测试与质量”）。
- 浏览器：桌面版 Chrome 或 Edge 最新版，使用未安装任何插件的干净配置。
- 测试语音：可合成（例如用语音合成生成英语句子），以浏览器“麦克风输入”的方式送入（真实麦克风收听外放，或作为麦克风设备的虚拟音频输入均可）。每段素材附带句子划分、每句起止时间与参考中文译文。无需人工提供素材。
- 时序记录：记录测试语音每句的起止时间，以及字幕区域每次变化的时间与内容，两者使用同一时钟。

## 测试策略

### 开发者验证

开发者在提交前以真实测试环境服务按 IQA-001～IQA-011 的步骤自测；可以另做不依赖外部服务的局部检查，但这些检查不能替代验收证据（宪章“测试与质量”）。

### Independent QA 验收

独立测试按“验收场景”逐条执行 IQA-001～IQA-011，全部在真实测试环境中进行，使用合成的英语测试语音及其参考译文；证据中不得包含凭据；测试语音为合成素材，其文本与译文可作为证据；IQA-008、IQA-009 只记录命中数量。

### 总体通过与失败标准

- 通过：IQA-001～IQA-011 全部通过，且 AC-01～AC-09 均有对应证据。
- 失败：任一 IQA 失败，或任一 AC 缺少来自真实测试服务的证据，或证据来自 Mock。
